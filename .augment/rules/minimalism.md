# Code Minimalism Rule

Code is a liability.

Follow these principles at all times:

- Prefer the smallest possible change that satisfies the request.
- Do NOT introduce new abstractions, helpers, or utilities unless strictly necessary.
- Do NOT refactor unrelated code.
- Do NOT add tests, comments, or documentation unless explicitly requested.
- Prefer modifying existing code over adding new files.
- If the task can be solved by changing configuration, comments, or usage instead of code, prefer that.
- If no code change is required, say so and explain why.
